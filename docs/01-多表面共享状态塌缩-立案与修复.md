# 01 · 多表面共享状态塌缩——立案与修复

> **状态：✅ 已修（插件 1.1.6，2026-09-30）**；平台层（SDK）正典**另立案**——壳仓 [12-多表面共享状态塌缩-立案.md](https://github.com/Encaron/linkdesk/blob/electron/docs/02-Electron%E6%9E%B6%E6%9E%84/%E6%8F%92%E4%BB%B6%E7%94%9F%E6%80%81%E4%B8%8E%E5%8F%91%E5%B8%83/01-%E6%8F%92%E4%BB%B6%E7%8B%AC%E7%AB%8B%E6%9E%84%E5%BB%BA/12-%E5%A4%9A%E8%A1%A8%E9%9D%A2%E5%85%B1%E4%BA%AB%E7%8A%B6%E6%80%81%E5%A1%8C%E7%BC%A9-%E7%AB%8B%E6%A1%88.md)（E6#158）。
> 定性一句话：**不是壳本体的问题，也不是「市场插件写错了」**——是 SDK 多表面打包的契约缺口（平台/作者轴）。

---

## 一、症状（用户实机立案，2026-09-30）

在插件市场侧栏点「**检查更新**」（1.1.0 起就有的那颗钮）：

- ✅ **侧栏探索列表**行内的「可更新」徽标**当场翻新**（作者刚发布的 1.1.5 出现）；
- ❌ **主区详情页不翻新**——版本下拉仍是旧值、更新钮不出现；
- ❌ 再点几次也没用；**退软件重进才一切正常**（重进后详情页拿到新目录）。

「同一份数据，一个面翻了、另一个面不翻」——这本身就是判据：**两个面读的不是同一个对象**。

## 二、现场取证（CDP，活的应用内，非源码推断）

1. 探针按「谁持有」给每个目录 store 实例打标后读到（原样 JSON）：

   ```json
   {"distinctEntryObjects":2,"list":[{"id":1,"ver":"1.1.5","owners":"ht,pt"},{"id":2,"ver":"1.1.4","owners":"ei"}]}
   ```

   **同一个 document 里并存 2 个不相同的 store 对象**：一个版本 1.1.5（刚被「检查更新」强拉过）、另一个 1.1.4（旧投影）——分别被侧栏面与主区详情面持有。

2. 同一 document 加载了**三份各自独立的表面 bundle**（`SearchView.bundle.js` / `DetailView.bundle.js` / `ExploreView.bundle.js`），**每一份里面都内联着一份共享模块的副本**（目录 store、搜索状态、已装列表 store……各自一套）。

## 三、根因链

```
SDK 多表面打包：一个插件 = 主入口 + 每个 contributes.views[].render 一份独立的 vite lib build
（壳仓 packages/plugin-sdk/src/vite-config.ts；design 见壳仓 01-插件独立构建/02-linkdesk-plugin格式规范.md:40）
        ↓
每份表面 bundle 单文件自包含（既定取舍：入口 default 导出零失真 + 逐表面失败隔离；
        代价原话 =「各表面共享模块重复打包（react 等壳 external 除外）」）
        ↓
ESM 模块身份 = URL ⇒ services/... 在 7 份 bundle 里各内联一份
        ↓
模块级可变状态（store / 守卫 / 去重表 / 订阅计数）在表面之间各长一个
        ↓
「模块级 = 跨视图唯一真相」这个前提【在单表面时代成立、在多表面时代静默失效】
```

**判据锚点**：`src/services/marketplaceShared/searchState.ts` 头部一直写着 E3.6 定的规矩「搜索状态必须是模块级的——`setSearch` 后所有 view 同步过滤」。这句**没有错**，它是按「所有 view 共用一个模块图」写的；E6#15 把每个 view 拆成独立 bundle 之后，这句话的成立前提被抽掉了，而**没有任何机制在抽掉时报警**——所以本缺陷不是谁手滑，是**契约缺口**。

**定性裁决**：

| 候选 | 判 |
|:--|:--|
| 壳本体（electron/main、pool 供给面） | **无辜**。壳按 URL 加载表面 bundle、事件广播、配置面全部按契约工作（壳侧本轮**零改动**） |
| 市场插件作者笔误 | **不是**。写的是标准模块单例 store，与壳仓既有 5 只官方插件同款；E6#15 之前这是唯一正确写法 |
| **SDK 多表面打包契约** | **就是它**。重复打包是**文档化了的有意取舍**，但「模块级可变状态会随表面复制」这一后果**没有被写进契约、没有作者面成规、没有机械腿**——「有意取舍」与「未交代后果」之间的缝，就是本缺陷 |

## 四、修复（插件侧，1.1.6）

**机制**：`src/services/realmSlot.ts`（新增）——**模块级可变状态不放模块作用域，放本 realm 的全局槽**。槽注册表挂在 `globalThis.__linkdesk_pluginSlots__<pluginId>`（必须带插件命名空间：池里所有插件共用一份 realm）；N 份表面副本从槽里取到的是**同一个对象**。

```ts
interface FooState { value: number; listeners: Set<() => void>; }
const state = realmSlot("fooStore", (): FooState => ({ value: 0, listeners: new Set() }));
```

**入槽清单（8 处，同族一并归位——不止报障那一条）**：

| 槽 key | 文件 | 状态域 | 修前症状/修后收益 |
|:--|:--|:--|:--|
| `catalogStore/v1` | `marketplaceShared/catalogStore.ts` | 目录投影（promise / result / listeners / gen / 配置监听守卫） | **报障的这一条**：侧栏翻新、详情页读旧投影；另修配置变更订阅「每表面一次」→「每 realm 一次」 |
| `searchState/v1` | `marketplaceShared/searchState.ts` | 搜索词 + 监听 | 🔴 **此前静默失效**：搜索框在侧栏表面、过滤在已装/探索表面——输入根本传不过去 |
| `pluginsStore/v1` | `marketplaceShared/pluginsStore.ts` | 已装/内置/禁用列表 + badge 广播 + burst 合并 | 每表面各拉一趟 IPC → 一份数据一趟 |
| `updateDiscovery.running/v1` | `updateDiscovery/run.ts` | 发现腿重入守卫 | 多表面可同时触发 → 每 realm 一趟 |
| `updateDiscovery.schedule/v1` | `updateDiscovery/schedule.ts` | 启动调度守卫 + 重试定时器 | 调度/定时器多份 → 一份 |
| `installFlow.openInstalls/v1` | `marketplaceShared/installFlow.ts` | 安装/更新去重 Map | 跨表面重复发起 → 真去重 |
| `commands/v1` | `marketplaceShared/commands.ts` | 命令注册守卫 | 多表面各注册一遍 → 一遍 |
| `installJobs/v1` | `installJobs.ts` | 安装任务快照 + `events.on` 订阅 | 每表面各订阅一次 → 一次订阅全表面收 |

**配套纪律（写进 realmSlot.ts 头部，后人照做）**：状态对象连同注释仍住原域文件（**每个域的状态归该域文件唯一属主**，别处走导出 accessor、不许直接摸槽）；**状态形状变了就换 key**（`"fooStore/v2"`——插件升级后旧副本可能还在同一 realm 里活着，同槽两形状会互相毒化）；**测试**：`vi.resetModules()` 只换模块实例、不换 `globalThis` ⇒ `vitest.setup.ts` 每例前 `__resetRealmSlots()`（等价于模块单例时代「每例全新实例」）。

**回归钉（修前全红、修后全绿——以 `git stash` 实测过）**：

- `src/__tests__/crossSurfaceSharedState.test.ts`（4 例，全部**跨模块实例**）：① 搜索状态写入 A 实例、B 实例读到并收到通知；② A 实例重投影后 B 实例可见且**全程只 1 次网络**；③ A 实例挂 hook 后 B 实例挂 hook **只发 1 趟 IPC**（`listCalls === 1`）；④ 两个模块实例的 hook **只产生 1 次 `events.on` 订阅**且都能收到广播。
- `src/__tests__/realmSlot.test.ts`（4 例）：同 key 同对象且 init 只跑一次 / 跨实例共享 / key 隔离与命名空间在场 / 清槽后 init 重跑。

**读数（1.1.6 收口时）**：`test` 31 文件 **437 例**绿 · `verify` 六段绿（lint 严 / 跨仓 import / 字典完整 / 声明自洽 / 图标绝对 URL / 覆盖）/ `build` **8/8 表面**（125.4 KB）且全部 7 份产物 bundle 内均含槽指纹 `__linkdesk_pluginSlots__marketplace` · **壳侧 `src/` `electron/` 零改动**。

## 五、根解两层（长期解在 SDK，不在本仓）

| 层 | 内容 | 状态 |
|:--|:--|:--|
| **插件侧（立即解，本版）** | realm 槽地基 + 8 处入槽 + 回归钉 | ✅ 1.1.6 |
| **平台层（长期解）** | SDK 二选一：(a) 跨表面共享模块**提升为共享 chunk**（多表面构建间去重，从根上保住「模块级 = 唯一真相」）；(b) SDK 提供**同名原语**（`realmSingleton()`）＋ 作者面成规「跨表面共享的可变状态必须走原语」＋ 可选机械腿 | 📋 立案：壳仓 [12 号档](https://github.com/Encaron/linkdesk/blob/electron/docs/02-Electron%E6%9E%B6%E6%9E%84/%E6%8F%92%E4%BB%B6%E7%94%9F%E6%80%81%E4%B8%8E%E5%8F%91%E5%B8%83/01-%E6%8F%92%E4%BB%B6%E7%8B%AC%E7%AB%8B%E6%9E%84%E5%BB%BA/12-%E5%A4%9A%E8%A1%A8%E9%9D%A2%E5%85%B1%E4%BA%AB%E7%8A%B6%E6%80%81%E5%A1%8C%E7%BC%A9-%E7%AB%8B%E6%A1%88.md)（E6#158）<br>🔴 **2026-09-30 用户拍板：(a) 是根治、(b) 是过渡**（判据 =「**这个缺陷类在平台层不再可能发生**」——含不可盘点的第三方仓与将来任何插件类型；(b) 的实质是把平台的债转成作者的纪律）⇒ **(a) 已单独立格 `E6#159`**，设计前置（8 维度 ＋ 两项未实证探针）＝ 壳仓 [13-跨表面共享chunk-设计前置.md](https://github.com/Encaron/linkdesk/blob/electron/docs/02-Electron%E6%9E%B6%E6%9E%84/%E6%8F%92%E4%BB%B6%E7%94%9F%E6%80%81%E4%B8%8E%E5%8F%91%E5%B8%83/01-%E6%8F%92%E4%BB%B6%E7%8B%AC%E7%AB%8B%E6%9E%84%E5%BB%BA/13-%E8%B7%A8%E8%A1%A8%E9%9D%A2%E5%85%B1%E4%BA%ABchunk-%E8%AE%BE%E8%AE%A1%E5%89%8D%E7%BD%AE.md) |

届时本仓 `realmSlot.ts` **整体换成 SDK 版、调用点一个不动**（现 API 形状就是照此预留的）。

## 六、有意不动的（范围外，如实记账）

- `marketSources/` 的 IO 注入点：目录 5 分钟缓存住 `localStorage`（**本就跨表面**），注入点只是测试替身面，无状态塌缩问题。
- `installedUpdateMeta.ts` 的 `_store`：测试注入旋钮，真实数据在壳侧 KV（`window.linkdesk.pluginState`），不属模块级可变态。
- 事件广播 `plugin:installJobs` 的 shell 侧会话缓存：池 preload 已做 replay-on-subscribe，正常跨表面；本轮只收敛**订阅次数**（installJobs 槽），语义不变。

## 七、验收与复验路径（🔴 含「为什么要重启」的判据）

- 复验动作：应用内「检查更新」拿到 **1.1.6** → **重启软件** → 点「检查更新」⇒ 侧栏行与主区详情页**同帧翻新**。
- 🔴 **为什么必须重启（不是本缺陷没修好）**：壳池按 URL `import()` 表面 bundle（`src/pool/shared/plugin-component/PluginComponent.tsx`，`@vite-ignore` 直 import，**不追加任何 cache-bust 查询**）——ESM 模块图按 URL 缓存，**同 URL 的模块不随磁盘替换而重载**。运行中的旧副本会一直活到重启，这是壳加载器的既有行为，已另记（与 E6 加载器优化同域，不阻塞本案）。
- 因此 1.1.6 的活体验证路径 = **重启后一次点击**；「不重启就翻新」不在本版承诺内。
- ⚠️ 老用户拿到 1.1.6 的通道 = **应用内更新（官方目录收录后）**或下一次带新种子的软件版（本仓同时是 `bundled-plugins/marketplace.linkdesk-plugin` 出厂种子，boot 只补缺失、**永不刷新已装**）。
